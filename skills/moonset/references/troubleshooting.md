# moonset Troubleshooting Guide

## 1. `.moonset/` State Files — Commit vs. Ignore

| File | Track in Git? | Purpose |
|---|---|---|
| `.moonset/release-state.json` | **YES (required)** | Generated by `moonset version`; read by `publish`, `tag`, and `release-notes --from-state` |
| `.moonset/version-journal.json` | **NO (gitignore)** | Atomic write transaction journal; deleted on success, used by `moonset version --recover` |
| `.moonset/publish-state.json` | **NO (gitignore)** | Per-unit publish cache for resuming partial failures; ignored by clean-tree check |
| `.moonset/pack-results.json` | **NO (gitignore)** | Local pack archive manifest and digest index |

Run `moonset doctor --fix` to generate a proper `.moonset/.gitignore` without overwriting existing files.

## 2. Interrupted `moonset version` (`version-journal.json` left behind)

- **Symptom**: `moonset doctor` or `moonset version` reports an unfinished `.moonset/version-journal.json`.
- **Fix**: Do **not** delete it blindly. Run:
  ```bash
  moonset version --recover
  ```
  Then verify `git status` and re-run `moonset status --output json`.

## 3. `publish` Fails with `dirty-working-tree` or `confirmation-required` (Exit Code 1)

- **Cause**: Uncommitted files exist after `moonset version`, or `--yes` was omitted in a non-interactive environment.
- **Fix**:
  ```bash
  git add -A && git commit -m "chore: release"
  moonset publish --yes --json
  ```
  Only use `--allow-uncommitted` for intentional local testing (note: it disables automatic `tag` creation on a dirty tree).

## 4. Partial Publish Failure (Exit Code 3)

- **Cause**: Network/registry error after some packages already published.
- **Fix**: Inspect `--json` output (`published` / `skipped` / `failed` / `blocked` / `unknown`). Fix the transient/auth issue and simply re-run:
  ```bash
  moonset publish --yes --json
  ```
  `moonset` uses `.moonset/publish-state.json`, remote Git tags, and registry `already_published` checks to resume idempotently without re-publishing succeeded packages. Do **not** delete `.moonset/publish-state.json` before resuming.

## 5. `moon publish --dry-run` Fails: `moon.mod.json is no longer supported`

- **Cause**: A transitive dependency resolved to an older package still using legacy `moon.mod.json`.
- **Fix**: Run `moon tree` to locate the legacy transitive dependency, then pin a migrated version in root `moon.mod` `import` until `moon publish --dry-run` passes.

## 6. `version-pr` Fails: `GitHub Actions is not permitted to create or approve pull requests`

- **Cause**: Repository or Organization blocks `GITHUB_TOKEN` from creating PRs.
- **Fix**: Enable **Settings → Actions → General → Workflow permissions → Allow GitHub Actions to create and approve pull requests** (check Organization settings if grayed out).

## 7. `MOONCAKES_CREDENTIALS` Auth Errors in CI

- **Cause**: `moon publish` reads `~/.moon/credentials.json` (JSON format), not a bare token string.
- **Fix**: Run `moon login` locally, copy the entire `~/.moon/credentials.json` JSON into the `MOONCAKES_CREDENTIALS` GitHub Secret, and pass `mooncakes-credentials: ${{ secrets.MOONCAKES_CREDENTIALS }}` to `unmbt/moonset@v1`.

## 8. Pushing a Release Tag Does Not Trigger `on: push: tags:` Workflows

- **Cause**: GitHub Actions intentionally prevents workflows triggered by default `GITHUB_TOKEN` from recursively triggering other `push` workflows.
- **Fix**: Call the binary/release workflow directly via `workflow_call` from `moonset-release.yml` instead of relying on tag push events or creating a PAT.
